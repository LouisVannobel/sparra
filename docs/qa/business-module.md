# Sparra business module — native inbox qualification

Task 2 adds the private owner inbox over the existing personal Workspace transaction. The module has no call creation/result production endpoint. The UI consumer belongs to Task 3.

## Qualified locally

- `listRequests` (GET, fixed 50 rows, descending millisecond admission/UUID tuple), `getRequestDetail` (GET), `markRequestTreated` (POST), `eraseRequest` (POST), and `getRequestErasure` (GET) use the native admitted principal, Workspace lock, caller signal and transaction completion boundary. Reads never create a Workspace. Inputs use strict Effect schemas, UUID normalization and canonical UTC millisecond cursors.
- `sparra_call` holds encrypted content and nullable immutable configuration pin. The composite FK cannot borrow a different Workspace's revision. Missing result, end observation and configuration remain absent. Runtime has SELECT and UPDATE on only `treated_at` / `erasure_requested_at`; it cannot insert calls, modify result/caller/configuration fields or delete rows.
- Runtime RLS requires the nonzero tenant text and matching active Workspace. The erase trigger's existing `workspace_owner` role instead has matching nonzero product scope because that role is not admitted by Workspace FORCE RLS. There is no new Workspace policy, membership or runtime function EXECUTE privilege. Native SQL verifies this composition, including UPDATE RETURNING followed by physical content absence and exactly one fence.
- Erasure records survive call removal and retention expiry. The trigger copies identity/retention from OLD, derives the original deadline plus 900 seconds, and commits queue creation with deletion atomically. An insertion fault rolls both back. A completed acknowledgment cannot release a fence early; a queued obligation cannot be deleted even after the deadline. The only acknowledgment in these tests is an explicitly privileged fixture update.
- Treatment is independent of call technical status and preserves its first timestamp. Expiry is checked with `clock_timestamp()` in business queries after Workspace acquisition, including an expiry reached while the Workspace was locked by another transaction.
- `SPARRA_AEAD_KEYRING_PATH` is the only key carrier, read only for rows with encrypted content. It must name an absolute regular non-symlink file, at most 16 KiB, with the strict Voice versioned keyring shape. There is no default/empty fallback or environment-file discovery. Missing keys, unknown versions, failed tags/AAD, invalid UTF-8 or invalid authenticated result yield bounded unavailable content.
- AES-256-GCM authenticates the separated final 16-byte tag before decoding plaintext. Turn plaintext is text. The proposed result uses `result:<call UUID>` AAD and a strict inner schema, with evidence limited to authenticated turns of this row. Only partial results with false confirmation flags are accepted. Mixed transcription failures remain explicit even when a result referencing other authenticated turns is valid. At most 200 turns are returned with an explicit truncation flag.
- Built native RPC verifies authentication, strict inputs, absent/foreign Origin, no-store/noindex/private CSP, bounded errors, and actual configured-path decryption. Cancellation before mutation leaves no state; cancellation on recorded PostgreSQL COMMIT rejects completion with committed outcome and a fresh receipt resolves the state.

## Remaining product boundaries

This is local native consumer qualification. There is no service ingest, live call, qualified complete result, booking/transfer confirmation, Voice erasure worker/ack consumer, or proof of physical remote/local-copy cleanup. Queue receipts do not claim that every copy is gone. The later bridge must consult the fence and reject expired original admissions even after eligible fence cleanup. No deployment or shared service migration was performed.
