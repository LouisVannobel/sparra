## Global Constraints

- The four application auth tables, migration and web/config/lifecycle/CSRF foundation already exist. Preserve/extend them; do not repeat their closed implementation or preparation reviews.
- All core auth methods and their recovery/email/session consumers remain required. A helper, schema, mock flow or Google-only milestone is not functional-auth completion; the other four SaaS deliveries remain after this plan.
- No CI/CD, production infrastructure, push, deployment, existing-service migrations or existing credential reuse. Local disposable dependencies explicitly authorized by the user must have checked local endpoints and unique template-owned names. No existing .env is read to create fixtures. Provider/account actions require an exact intended environment/operation; a secret being present is not authority.
- Exact pins, one normative typecheck, source/tests of the installed version before generic docs. Main/implementers read relevant native Effect/TanStack/Better Auth instructions fully; project invariants override their unrelated setup examples. No new SQL stack, password, shadcn, fake provider fallback, generic repository or proof controller.
- One source writer, fresh implementer per task, behavioral RED before production code, independent spec/quality review then Oracle for the step. Source/transport-double tests and live PostgreSQL/provider/browser acceptance are reported separately.
- Better Auth alone owns session token/id/expiry/signing/validation/revocation. No fabricated accepted session or cast restoring filtered private fields. App-owned magic tokens are purpose-bound, one-way verified, single-use and generation-checked; encrypted delivery material follows the adopted exception.
- All private server functions enforce the current principal before reading tenant/private resources. Public BA methods/paths default-deny, one handler mount, sensitive operations in named server-only commands. No auth/profile data in public cache, browser logs, error output or telemetry.
- One physical pg owner, READ COMMITTED/sentinel before handle exposure, same-owner nesting, FIFO/drain/invalidation and bounded cleanup. No raw native Drizzle transaction, pool.query business transaction, savepoint or unchecked release after ambiguous completion. Never hold a DB checkout over provider I/O.
- Only the worker calls Plunk. Request/command/delivery/outbox durability and replay identity are database-owned, not deferred-hook or Hatchet guarantees. Unknown provider outcomes remain unknown; no new key or fresh token on retry.
